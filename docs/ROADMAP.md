# Next work, driven by evidence

This is a proposed sequence, not a delivery promise.

1. **Validate the public starting point.** Independent developers should complete setup, import/edit/walk/export and one extension without private files or maintainer help. Record failures with the real-use template.
2. **Measure useful outcomes.** Run the campus-review, data-preparation and developer-extension pilots in `VALUE_AND_VALIDATION.md`. Decide what to improve from observed task failures and paired comparisons.
3. **Establish device and recovery coverage.** Test physical target devices, keyboard/touch use, storage exhaustion, stale-tab conflicts and prolonged sessions with representative data. Format ceilings are not performance promises.
4. **Package stable boundaries only after use.** Separate the map model, conversion and runtime where integrations demonstrate a reusable API. Version compatibility deliberately.
5. **Choose the next product capability.** Complete world archives, shared editor persistence, authoritative networking, avatar/vehicle authoring and a time-varying world model are distinct projects. Each needs an explicit scope and acceptance evidence.

The draft contracts are design inputs. They do not implement the future capabilities. Optional WASM/GPU expansion should follow measured end-to-end benefit on target devices.
